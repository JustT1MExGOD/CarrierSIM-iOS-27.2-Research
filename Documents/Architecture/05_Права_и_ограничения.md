# Учётные записи и ограничения процессов

Исполнение под root или системной учётной записью само по себе **не** означает право записи
в `/var/mobile/Library/Carrier Bundles/iPhone`. Решающие факторы — область sandbox и
назначение MachService.

## Подтверждённые учётные записи

Из launchd-определений Beta 3:

| Служба | Пользователь | Область |
|---|---|---|
| `com.apple.CommCenter` | `_wireless` | телефония; `baseband` device-tree |
| `com.apple.mobile.installd` | `_installd` | установка приложений/пакетов |
| `com.apple.streaming_zip_conduit` | `mobile` | потоковая загрузка ZIP |
| `com.apple.atc` | `mobile` | медиа-синхронизация |
| `com.apple.dataaccess.dataaccessd` | `mobile` | аккаунты (почта/контакты/календарь) |

**Высокая** — все значения прочитаны из launchd-определений.

## Что это означает для carrier bundles

- Только `CommCenter` (`_wireless`) и `installd` (`_installd`) являются подтверждёнными
  «письмами» операторской конфигурации — но через специализированные сервисы
  установки подписанных артефактов, а не через общий API «записать файл».
- `atc` работает под `mobile` и ограничен `/var/mobile/Media` — он никогда легально не
  писал в `/var/mobile/Library`; его путь был нестандартным.
- `dataaccessd` тоже под `mobile` — та же граница Media, та же бесполезность для записи
  carrier bundles.

## Механизм ограничения (то, что подтверждено)

- Ошибка `107` — отказ ядра/песочницы, возвращаемый системным вызовом перемещения. Это
  не пользовательская проверка пути в atc, а kernel-side отказ. **Высокая** (значение errno
  и его природа capability); **средняя** для точного вида проверки (Seatbelt vs vnode).
- Общий дескриптор `x24` передаётся между вызовами как dirfd — якорь для разрешения путей.
  Сам по себе dirfd `..` не ограничивает; отказ наступает на уровне ядра при разрешении в
  запрещённую область. **Высокая** для поведения; **средняя** для полного объяснения.
- `fileproviderd` — отдельный процесс, его `deny(1) file-read-data` на
  `/private/var/mobile/Library` иллюстрирует тот же sandbox-контур, но **не** доказывает
  участие в перемещении. **Высокая.**

## Корректировка к прежним отчётам

Прежние отчёты иногда связывали отказ с тем, что dirfd «изолирует» путь. Уточнение:
ограничение даёт связь «dirfd-якорная разрешение в ядре + kernel capability check», а не
сам дескриптор. `O_NOFOLLOW` на `open` не обнаружен; `RENAME_NOFOLLOW` подтверждён на
`renameatx_np`. **Высокая.**
