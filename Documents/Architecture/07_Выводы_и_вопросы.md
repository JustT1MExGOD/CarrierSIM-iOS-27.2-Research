# Выводы и открытые вопросы

## Подтверждённые выводы (высокая уверенность)

1. **Прежний механизм Airlift закрыт.** Перемещение теперь выполняется операциями
   относительно файлового дескриптора каталога с kernel-level отказом `107` (capability
   domain) для путей за пределами `/var/mobile/Media`. Подтверждено на RC `24B119`.
2. **Отказ — kernel-side.** Ошибка возвращается системным вызовом, а не пользовательской
   проверкой строки. Старая строковая проверка Beta 2 (`Cannot move asset outside of AFC
   root`) была обходима симлинком `../../`; новая схема устраняет этот обход на уровне ядра.
3. **Владельцы определены.** `CommCenter` (`_wireless`) — операторская конфигурация;
   `installd` (`_installd`) — официальная установка пакетов; `atc` (`mobile`) — только
   медиа-синхронизация внутри `/var/mobile/Media`.
4. **Штатная установка ≠ произвольная запись.** IPCC обновляет операторские настройки, но
   не воспроизводит инъекцию чужого операторского профиля в живой каталог.
5. **fileproviderd — не исполнитель перемещения.** Отказ на этом процессе — смежное событие
   чтения при параллельном подсчёте дискового пространства, а не механизм перемещения.

## Открытые вопросы (средняя/низкая уверенность)

- **Точные имена вызовов.** `open`, `mkdirat`, `renameatx_np`, `unlinkat` разрешены по форме
  аргументов, не по таблице импортов AirTraffic. Для `renameatx_np` сигнатура наиболее
  ограничительна (5 аргументов, два dirfd), остальные — сильные, но не табличные.
- **Значение `0x40000000`.** Лучшая рабочая интерпретация — `O_EXECONLY` (search-only dirfd);
  альтернатива — приватный флаг resolve-beneath. Макроимя не подтверждено без SDK `fcntl.h`.
- **Вид проверки ядра.** Отказ — kernel capability errno; конкретная проверка (правило
  Seatbelt vs vnode/domain) не разграничена.
- **RC-бинарник.** Поведение RC подтверждено идентичным Beta 3, но сам RC-бинарник не
  извлечён и не сравнивался побайтно.
- **fileproviderd.** Скорее всего независимое событие чтения, но делегирование перемещения
  через него доказать нельзя.

## Что прежние отчёты утверждали без достаточных оснований (корректировки)

- «dirfd сам по себе изолирует/джейлит путь» — **уточнено**: ограничение даёт
  dirfd-якорная разрешение в ядре + kernel capability, а не один дескриптор.
- «errno 107 = ENOTCAPABLE как факт» — **смягчено**: значение и текст подтверждены, имя
  константы — гипотеза (сдвиг индекса в `sys_errlist`, нет локального заголовка).
- «использован O_NOFOLLOW» — **опровергнуто**: `O_NOFOLLOW` отсутствует; на `renameatx_np`
  используется `RENAME_NOFOLLOW` на финальный компонент.
- «fileproviderd выполнял перемещение» — **опровергнуто**: перемещение выполняется внутри
  `atc`, fileproviderd — отдельный процесс с отказом чтения.

## Итоговая оценка перспектив

Подтверждённого штатного механизма для произвольной записи CarrierSIM в каталог **не
найдено** (`NOT FOUND`). Официальные каналы (IPCC, OTA, eSIM, MDM, UI) покрывают штатное
обновление операторских настроек, но не дают произвольно изменять живой каталог, как это
делал прежний путь. Восстановление специфической операции потребует принципиально новых
исследований за пределами документированных механизмов — и это уже исследование, а не
поддерживаемое решение.
