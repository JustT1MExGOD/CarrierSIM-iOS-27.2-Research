# Архитектура iOS и системные механизмы операторских настроек

Дополнение к основному исследованию регрессии Airlift. Здесь собрана **статическая инвентаризация**
компонентов iOS, отвечающих за carrier bundles, и оценка того, есть ли штатный (документированный)
путь выполнения тех же операций, что прежде делал AirTraffic/Airlift.

Раздел основан на двух независимых наборах свидетельств:

- `launchd`-определения служб, прочитанные напрямую из файловой системы сборки 27.2 Beta 3
  (`24B5099f`);
- статический разбор бинарников `atc`, `AirTraffic.framework`, `installd`, `amfid` и журнала
  одного диагностического запуска на RC `24B119`.

## Главный вывод

Подтверждённого штатного механизма, который выполнял бы для CarrierSIM произвольную запись в
`/var/mobile/Library/Carrier Bundles/iPhone`, **не найдено** (`NOT FOUND`). Официальные каналы
покрывают штатное обновление операторских настроек (IPCC), но не дают произвольно изменять
живой каталог, как это делал прежний путь.

Уровни уверенности в этом разделе соответствуют принятой в репозитории шкале:
**высокая** (прямая свидетельство), **средняя** (обоснованная интерпретация), **низкая**
(предположение / недостаточные данные). Отдельно помечено то, что прежние отчёты утверждали без
достаточных оснований.
