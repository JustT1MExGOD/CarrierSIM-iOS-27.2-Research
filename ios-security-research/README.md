# Независимое исследование безопасности iOS 27.2+ (Phase 1–5)

Открытый набор технических отчётов об автономном статическом анализе системных
компонентов iOS 27.2 (Beta 2 / Beta 3 / RC), выполненном после исследования
регрессии CarrierSIM / Airlift.

**Главный вывод, честно:** на момент завершения Phase 5 новых подтверждённых
уязвимостей iOS не обнаружено. Это не отрицательный результат — это результат,
полученный с корректной методологией отрицания.

## Связь с исследованием CarrierSIM/Airlift

Исходная работа по CarrierSIM ([README](../README.md)) исследовала один конкретный
канал записи в `/var/mobile/Library/Carrier Bundles/iPhone` через `atc`/AFC и
документировала его закрытие на Beta 3 (errno 107, `Capabilities insufficient`).
В ходе этого анализа был собран корпус разобранных системных бинарников
(`installd`, `amfid`, `atc`, `AirTraffic`) Beta 2/Beta 3. Phase 1–5 — это
независимая проверка этого корпуса: уже не «как выполнить операцию», а
«содержат ли сами исследованные компоненты подтверждаемый дефект безопасности».

Два исследования связаны материалами, но не целями: первое документировало
регрессию пользовательской техники, второе — аудит защищённости самих сервисов.

## Метод

Только статический офлайн-анализ локального корпуса. Не проводилось:

- взаимодействие с устройством;
- фаззинг системных служб;
- тесты гонок на реальных системных компонентах;
- создание полезных нагрузок;
- разработка обходов sandbox / повышений привилегий / цепочек эксплуатации;
- модификация системных бинарников.

Каждая фаза оформлена отдельно; статус каждого кандидата пересматривался
независимо, а не наследовался из предыдущей фазы.

## Исследованные компоненты

- `installd` (`_installd`) — установка/обновление приложений, delta-patch.
- `amfid` — оценка подписей кода, `vm_read` из удалённой задачи.
- `atc` — демон медиа-синхронизации (хост AirTraffic).
- `AirTraffic` — обработка Airlift-ассетов (сравнение B2↔B3).

## Проверенные гипотезы

Восемь кандидатов (IOS-SEC-001 … 008) — авторизация NSXPC installd, test-mode
регистрация, гипотеза double-fetch `vm_read` в amfid, парсер delta-манифеста и
TOCTOU в installd, операции AirTraffic через directory-FD, различия парсинга
entitlements и ограничения классов unarchiver'а. Подробности в
[RESEARCH_STATUS.md](RESEARCH_STATUS.md) и отчётах фаз.

## Что подтверждено

- Модель авторизации installd NSXPC (75 экспортируемых методов, per-method
  entitlement gate) — архитектурное наблюдение, не дефект.
- Отсутствие double-fetch в amfid: два разных `vm_read` из разных источников.
- Бинарный формат delta-манифеста `ipaD` и его bounded line-reader парсер.
- Path-based file-ops в `hardlink_copy_hierarchy` без destination dirfd anchor.
- Делегирование staging-операций через helper-service XPC.

## Что осталось открытым

- Точные UID/GID/mode/ACL staging-каталогов и `existingBundleContainer`.
- Полный effective writer set для домена AppBundles.
- Полные sandbox-профили installd и helper-service (не декомпилированы).
- Фактический результат `removeACLs` для каждого пути.
- Object identity между check и use в path-based операциях (отсутствие FD anchor).
- Значимое security consequence при гипотетической мутации пути.

## Честность статусов

`INSUFFICIENT EVIDENCE` означает именно то, что написано: доказательств
уязвимости недостаточно — но и доказательств её невозможности тоже. Phase 4
присвоила IOS-SEC-004 статус `RULED OUT`, опираясь на intended trust model;
Phase 5 показала, что это перешагивает доступное evidence, и понизила статус.
`NOT VERIFIED` не приравнивается к `CONTRADICTED`.

## Структура

- [RESEARCH_STATUS.md](RESEARCH_STATUS.md) — сводная матрица результатов.
- `PHASE1/` — инвентаризация, границы доверия, реестр кандидатов.
- `PHASE2/` — независимая верификация восьми кандидатов.
- `PHASE3/` — углублённый анализ delta-manifest parser.
- `PHASE4/` — staging-каталоги, файловые операции, гипотеза TOCTOU.
- `PHASE5/` — аудит доказательств и корректировка итоговых статусов.
- `evidence/` — entitlements, протокол, минимальные фрагменты дизассемблирования
  с указанием версии и адресов (полные дампы не публикуются).

## Границы публикации

Не публикуются: IPSW/OTA, извлечённые проприетарные бинарники Apple, dyld shared
caches, полные дампы дизассемблирования, личные данные, идентификаторы
устройств, токены, сырые журналы с чувствительными сведениями. Фрагменты кода
приведены в минимально необходимом объёме для проверки выводов.

**Это исследовательская документация, а не инструкция по эксплуатации.**
