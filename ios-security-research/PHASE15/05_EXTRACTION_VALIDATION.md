# Phase 15 · Отчёт 05 — Валидация Phase 11 extractor

## 1. Назначение документа

Проверка корректности `PHASE11\extract_flat.py` — инструмента, которым были
получены рабочие Mach-O (`amfid_B3.bin`, `installd_B3.bin` и др.) из dyld
cache. Цель — подтвердить, что extracted-образы пригодны как доказательство
и что дефект Phase 10 устранён.

## 2. Что исправлялось относительно Phase 10

- Phase 10 трактовал dyld-cache-глобальные `fileoff` как локальные смещения
  внутри отдельного извлекаемого файла → сегменты накладывались друг на
  друга, извлечённые Mach-O были повреждены.
- Phase 11 (`extract_flat.py`) пакует доступные сегменты компактно:
  заголовок+load commands в начале, далее сегменты, выровненные по 4K;
  переписывает `LC_SEGMENT_64.fileoff` и `section.offset`; **сохраняет**
  `vmaddr`; недоступный `__LINKEDIT` **опускает**, а не подделывает.

```python
header_end = 0x20 + sizeofcmds
cursor = (header_end + 0xfff) & ~0xfff
for segname, vmaddr, vmsize, fileoff, filesize, _cmdoff in segments:
    if not segment_present[segname]:
        new_fileoffs[segname] = 0
        continue
    new_fileoffs[segname] = cursor
    cursor += (filesize + 0xfff) & ~0xfff
```

## 3. Проверки качества извлечённых образов

| Проверка | Результат |
|---|---|
| Mach-O magic `0xfeedfacf`, arm64e | подтверждено на `amfid_B3`, `installd_B3` |
| `LC_UUID` читается и стабилен | `amfid_B3` `CFB0C004-…`, `installd_B3` `F54A48D1-…` |
| Размеры соответствуют ожиданию | `amfid` 253 968, `installd` 961 888, `atc` 84 160 |
| Перекрытия сегментов Phase 10 | устранены (компактная упаковка) |
| `__LINKEDIT` отсутствует | **ожидаемо** — физические данные зашифрованы в cryptex |
| SHA-256 сходится с ранее зафиксированными | `amfid_B3` `d331a101…`, `installd_B3` `1dd5efbf…` |

## 4. Пригодность как доказательство

- Кодовые сегменты (`__TEXT`, `__AUTH_CONST`) извлечены корректно и дают
  воспроизводимый дизассемблер (подтверждено анализом `sub_100004030` в
  Phase 12 — разбор сходился с адресами `0x100004264` и т.д.).
- **Ограничение**: без `__LINKEDIT` нет export-trie, bind/rebase opcodes,
  chained fixups и code signature. Поэтому извлечённые образы годятся для
  анализа `__TEXT`/констант, но **не** для резолва импортов/селекторов —
  что и подтверждает ограничение Phase 14 (`bl #0x2794e50`/`#0x3383500`
  остались stub-функциями без разрешённых имён).

## 5. Вывод

`extract_flat.py` корректен для доступной части образов; дефект Phase 10
устранён. Извлечённые Mach-O валидны как доказательство уровня A для
`__TEXT`-анализа. Невозможность резолва импортов — следствие зашифрованного
`.dyldlinkedit`, а не дефект extractor.
