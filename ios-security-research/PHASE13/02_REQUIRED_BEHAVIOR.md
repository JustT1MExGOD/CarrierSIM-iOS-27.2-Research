# Фаза 13 — необходимый результат

## 1. Цель

Для SIM оператора A система должна выбрать уже существующий Apple carrier bundle оператора B. Исторический CarrierSIM добивался этого созданием в пользовательском каталоге `/var/mobile/Library/Carrier Bundles/iPhone` симлинка `<IMSI> -> /System/Library/Carrier Bundles/iPhone/<B>.bundle`. Целевые пакеты: `Vodafone_hu.bundle`, `Vodafone_ro.bundle`.

## 2. Разделённые этапы (не смешивать)

### 2.1. Физическое размещение ссылки
Создать файловый объект-симлинк в `/var/mobile/Library/Carrier Bundles/iPhone` с именем 15-значного IMSI. Это **запись в защищённый пользовательский каталог**. Именно здесь ломался Airlift — не на выборе bundle, а на записи.

### 2.2. Регистрация bundle
Системный `.bundle` уже зарегистрирован (Apple-signed bundle в `/System/Library/Carrier Bundles`). Новый IMSI-симлинк — алиас к уже существующему bundle, не установка нового.

### 2.3. Сопоставление SIM↔bundle
CommCenter сопоставляет IMSI подписчика с записью каталога. 15-значный IMSI-алиас имеет наивысший приоритет над MCCMNC-именованными записями — механизм, который CarrierSIM эксплуатировал.

### 2.4. Выбор активного bundle
CommCenter при пересканировании (после IPCC install / rescan) выбирает bundle по правилам приоритета. Точные правила — внутри CommCenter (не извлечён); наблюдаемо IMSI-алиас побеждает.

### 2.5. Применение настроек
Выбранный bundle отдаёт carrier.plist → APN, VoLTE, IMS, VoWiFi параметры CommCenter'у.

### 2.6. Фактическая активация VoWiFi
Зависит от: поддержки bundle'ом IMS/Wi-Fi Calling, разрешения оператора на стороне сети, корректной регистрации IMS, настроек устройства. Выбор bundle — **необходимое, но не достаточное** условие.

## 3. Что реально необходимо для эквивалентного результата

Необходимое и достаточное условие исторического механизма — **существование корректного IMSI-симлинка в пользовательском каталоге до пересканирования CommCenter**. Все остальные пути либо устанавливают настройки, но не создают IMSI-алиас к чужому bundle (IPCC сам по себе), либо не дают записи в защищённый каталог вообще.

## 4. «Сопоставление» vs «запись»

- **Сопоставление SIM→bundle** CommCenter делает автоматически по IMSI/PLMN/GID.
- **Принудительное сопоставление к ЧУЖОМУ bundle** требует IMSI-алиаса, которого штатно нет — его надо создать.

Вопрос Phase 13 сводится к: «существует ли поддерживаемый способ создать IMSI-алиас (или эквивалентную привязку SIM→чужой-bundle) на iOS 27.2+ без прямой записи в защищённый каталог».

## 5. Вывод

Необходимый результат = привязка IMSI к чужому bundle на уровне разрешения CommCenter. Единственный исторически известный механизм — файловый IMSI-симлинк в `/var/mobile/Library/Carrier Bundles/iPhone`. Любая альтернатива должна либо создавать эквивалентную запись, либо напрямую управлять логикой выбора CommCenter. Штатный IPCC сам по себе такой привязки не создаёт.
