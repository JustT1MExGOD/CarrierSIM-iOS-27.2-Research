# PHASE7 — 06_INFORMATION_CLASSIFICATION

## getSEPStateWithReply: — классификация полей ответа

Структура `{?=III{?=C{?=I[32C]}}}` (49 байт):

| Поле | Происхождение | Назначение (предпол.) | Публично? | Признаки конфиденциальности | Уверенность |
|---|---|---|---|---|---|
| 3 × u32 | LAStorage key 0xf, поля записи | версия/счётчик/state флаги SEP-записи | Нет публичного API на LAStorage key space | Низкие: счётчики/флаги — метаданные | MED (по размеру/типу) |
| u8 flag | то же | булев/enum признак (лог `[exists: %u]` указывает на отдельный exists-флаг) | Нет | Низкие | MED |
| вложенный u32 | то же | inner count/state | Нет | Низкие | MED |
| C[32] blob | то же | digest/UUID/метка записи (размер SHA-256) | Нет | Умеренные: если это digest — метаданные; если ключевой blob — высокие. По семантике LAStorage скорее **идентификатор/хэш записи**, не raw key | MED–LOW, семантика NOT VERIFIED |

**Итог по getSEPState:** системные метаданные состояния SEP-related записи. Признаков секретов (ключевой материал, PII) по layout нет. Класс: **диагностические/системные метаданные, LOW–MEDIUM sensitivity**.

## getStagedProfileWithReply: — классификация

| Поле | Происхождение | Назначение | Публично? | Конфиденциальность | Уверенность |
|---|---|---|---|---|---|
| NSString целиком | `/private/var/db/amfid/UPPStaging.plist` | staged provisioning UUID (по write-side `stageProfileForUuid:`) | Нет публичного API к этому файлу | UUID — opaque-идентификатор: низкая прямая чувствительность; умеренная как индикатор pending-provisioning state и потенциальный oracle | HIGH для типа, MED для семантики |

**Итог по getStagedProfile:** системный идентификатор состояния. Класс: **системные метаданные, LOW–MEDIUM sensitivity**; масштаб растёт только если файл когда-либо хранит больше UUID — тогда возвращается всё без фильтрации (unbounded disclosure by design).

## Разграничение классов

| Класс | Применимо? |
|---|---|
| Общедоступное состояние | Нет — ни одно из полей не доступно через публичные API |
| Диагностические сведения | Частично — оба ответа по форме похожи на диагностику/статус |
| Системные метаданные | **Да — основная классификация обоих** |
| Потенциально чувствительная информация | Только 32-байтовое поле SEP-state при неблагоприятной семантике; staged-UUID как oracle — слабо |
| Неустановленное содержимое | Семантика полей обеих структур + возможное дополнительное содержимое UPPStaging.plist |

## Что точно НЕ раскрывается

- Криптографические ключи, пароли, токены — по типам полей и источникам не присутствуют.
- Полный provisioning profile — `getStagedProfile` возвращает текст файла, который по write-side содержит UUID, не сертификаты.
- Любые данные клиента другого XPC-соединения — ответы формируются только из постоянного system-state.

## Достаточность доказательств

Для утверждения «утечка секретов» доказательств нет: ни одно поле не идентифицировано как protected credential. Для «раскрытие метаданных системного состояния» доказательства есть: оба метода стабильно отдают нетривиальное состояние доверенной подсистемы без caller-проверки в теле.
