# Семантика `validateWithError:`

## 1. Важное разделение уровней

В доступных данных необходимо различать четыре разных утверждения:

1. **Селектор:** строка/вызов `validateWithError:` присутствует.
2. **Реализация:** тело метода и его внутренние ветви восстановлены.
3. **Получатель:** вызов отправляется объекту, созданному как `AMFIPathValidator_ios`.
4. **Вывод о политике:** можно утверждать, какие комбинации результатов допустимы для клиента.

Первое и третье подтверждены напрямую. Второе и четвёртое — нет.

## 2. Получатель и динамическая диспетчеризация

Перед вызовом по `0x1000041a0–0x1000041b4` загружается ObjC-класс `AMFIPathValidator_ios`, выполняется `objc_alloc`, затем `initWithURL:withFileOffset:withFlags:`. Вызов по `0x1000041c4` — это `objc_msgSend(x0, "validateWithError:")`.

Это доказывает ожидаемый класс объекта на статически видимом пути. Однако `objc_msgSend` остаётся динамической диспетчеризацией: по одному call site нельзя восстановить тело метода, возможность переопределения, внутренние вызовы или точное значение ошибки.

## 3. Что говорят окружающие данные

В Beta 2 `AppleMobileFileIntegrity_B2.dylib` найдены отдельные группы строк, относящиеся к:

- ошибке подписи/CodeDirectory;
- отсутствующей или неподходящей provisioning profile;
- несовпадению сертификатов и entitlement;
- отсутствию auxiliary signature.

Это поддерживает многомерную модель результата, но строки сами по себе не доказывают достижимость конкретной ветви и не доказывают порядок возврата из `validateWithError:`.

## 4. Две конкурирующие модели

### Модель A — независимые оси

Метод может признать подпись действительной, отдельно установить профильный результат как отрицательный и вернуть общий успех для передачи составного результата дальше. Тогда комбинация `isValid=1, profile_valid=0` достижима.

### Модель B — единый итоговый gate

Метод может считать успехом только одновременное прохождение подписи, entitlement и profile-проверки. Тогда profile-сбой изменит общий результат, и отдельное положительное `isValid` не будет иметь самостоятельного значения.

Доступный call site различает выходные поля, но не выбирает между моделями A и B.

## 5. Важное ограничение

Нельзя выводить семантику `validateWithError:` из одного только порядка последующих вызовов `isValid`, `areEntitlementsValidated` и `profileData`. Этот порядок доказывает, что данные читаются после ненулевого возврата метода, но не говорит, какие проверки уже были включены в этот возврат.

## 6. Вывод

Селектор, предполагаемый класс получателя и последующее извлечение нескольких полей подтверждены. Реализация метода и его контракт для частично успешных результатов недоступны. Поэтому P9-H1 не может быть повышена до подтверждённой уязвимости.
