# Семантика потребителей

## 1. Подтверждённые узлы

Локально подтверждена следующая цепочка:

```text
MIG verify_code_directory request
    → sub_10000b194
        → sub_100004030
            → AMFIPathValidator_ios
                → validateWithError: (динамический вызов)
            → result fields
        → MIG reply packing
```

`sub_10000b194` — подтверждённый внутренний потребитель результата `sub_100004030`. Это не доказывает наличие внешнего потребителя в локальном наборе файлов.

## 2. Не найденный клиент

В доступных материалах нет бинарника, который бы надёжно показывал, как ответ `verify_code_directory` используется после получения. Не восстановлены конкретные проверки клиентом:

- обязательность `isValid`;
- обязательность profile-флага;
- связь `areEntitlementsValidated` с разрешением операции;
- требование `profileAuxSig` для конкретного класса профиля;
- реакция на ошибку копирования при сохранённом первичном результате.

Названия возможных клиентов (`misagent`, online-auth или XPC-потребитель) не являются доказательством их присутствия.

## 3. Независимый путь `installd`

В дизассемблировании Beta 3 `installd` обнаружен собственный путь через `MICodeSigningVerifier` и `MICodeSigningInfo`. Он включает независимую проверку подписи/идентификатора при установочных и eligibility-сценариях.

Этот путь важен как defense in depth: даже если какой-либо MIG-ответ трактуется неоднозначно, установочный потребитель может не использовать его как единственный источник решения. Но наличие собственного пути не доказывает, что каждая операция проходит через него.

## 4. Что требуется для закрытия вопроса

Нужен хотя бы один реальный клиентский бинарник с:

1. вызовом соответствующего IPC/MIG-интерфейса;
2. разбором `reply+0x24`, `+0x28`, `+0x34`, `+0x38`;
3. ветвлением по комбинациям полей;
4. последующим security-sensitive действием.

Такая проверка должна выполняться статически; активные IPC в рамках проекта не нужны.

## 5. Вывод

Потребительская семантика P9-H1 не установлена. Producer-код доказывает передачу частично заполненного результата, но не доказывает, что какой-либо клиент превращает его в разрешение защищённой операции.
