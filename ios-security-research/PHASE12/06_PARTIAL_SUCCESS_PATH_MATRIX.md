# Матрица частично успешных путей

## 1. Обозначения

- `V` — `validateWithError:` вернул ненулевой результат.
- `PD` — `profileData` присутствует.
- `PR` — вызов `vm_read` для `profileData` успешен.
- `AS` — `profileAuxSig` присутствует.
- `AR` — вызов `vm_read` для `profileAuxSig` успешен.
- «Первичные поля» — значения, полученные через `computedCdHash:withLength:`, `signerType`, `isValid`, `areEntitlementsValidated`.

## 2. Матрица

| Сценарий | Наблюдаемое поведение | Статус |
|---|---|---|
| `V=0` | последующие поля не извлекаются; предварительно обнулённые выходы сохраняются; выполняется ошибочный/завершающий путь | прямо подтверждено частично |
| `V=1, PD=0` | первичные поля извлекаются; профильные данные отсутствуют; управление идёт к обработке `profileAuxSig` | прямо подтверждено |
| `V=1, PD=1, PR=1` | профильные bytes/length передаются в `vm_read`; устанавливается профильный success-like флаг | прямо подтверждено |
| `V=1, PD=1, PR=0` | два профильных выхода обнуляются; управление переходит к `0x1000042b8`, а не к terminal cleanup | прямо подтверждено |
| `V=1, AS=0` | auxiliary-данные не копируются; функция продолжает завершение | прямо подтверждено |
| `V=1, AS=1, AR=1` | auxiliary-данные копируются; устанавливается auxiliary success-like флаг | прямо подтверждено |
| `V=1, AS=1, AR=0` | ошибка журналируется; auxiliary-выходы обнуляются; функция продолжает завершение | прямо подтверждено |

## 3. Наиболее важный путь P9-H1

Путь `V=1, PD=1, PR=0` показывает, что после успешного возврата валидатора может произойти независимый сбой получения профиля. Код не возвращается к началу проверки и не обнуляет ранее извлечённые первичные поля в видимом фрагменте. Он обнуляет профильные выходы и продолжает auxiliary-обработку.

Это доказывает архитектуру частично сохранённого результата при **ошибке передачи/чтения данных**. Это ещё не доказывает частичный успех при **ошибке проверки профиля**: причина отказа `vm_read` и причина profile mismatch — разные классы событий.

## 4. Что не следует из матрицы

- Нельзя назвать любой `V=1` полным успехом доверия.
- Нельзя считать `profileData` единственным источником profile validity.
- Нельзя считать продолжение control flow доказательством положительного MIG status.
- Нельзя считать нулевые профильные выходы доказательством отсутствия профиля в исходном объекте.

## 5. Итог

Достижимый частичный путь подтверждён на уровне producer-кода, но его семантика для безопасности не установлена без точного MIG-клиента и тела `validateWithError:`.
