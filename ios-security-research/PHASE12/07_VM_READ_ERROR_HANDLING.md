# Обработка ошибок `vm_read`

## 1. Контекст

В `sub_100004030` `vm_read` применяется не к проверке криптографической подписи, а к копированию уже полученных ObjC-объектов (`profileData` и `profileAuxSig`) в память, пригодную для передачи через MIG.

Поэтому ошибку `vm_read` нельзя автоматически классифицировать как отказ подписи или CodeDirectory.

## 2. `profileData`

Последовательность:

1. `profileData` запрашивается через `objc_msgSend`.
2. При нулевом объекте копирование пропускается.
3. При ненулевом объекте читаются `bytes` и `length`.
4. Вызывается `vm_read`.
5. При успехе устанавливается профильный success-like флаг.
6. При ошибке обнуляются `[sp,#0x60]` и значение, связанное с `[x19]`.
7. Выполняется переход в `loc_1000042b8`, начало обработки `profileAuxSig`.

Журналирование ошибки `profileData` в показанном фрагменте не обнаружено; это не позволяет считать ошибку криптографической.

## 3. `profileAuxSig`

Последовательность аналогична до `vm_read`. При ошибке выполняются:

```text
stp x24, x0, [sp]
add x1, x1, #0x236
mov w0, #0x3
bl  j__syslog
str xzr, [x20]
str wzr, [x27]
```

Строка журнала: `unable to vm_read profileAuxSig: %d`. После очистки функция продолжает финальный путь.

## 4. Классификация ошибок

| Событие | Класс | Что можно утверждать |
|---|---|---|
| `validateWithError:` вернул отказ | криптографическая/политическая проверка, точная причина недоступна | первичные выходы не получают обычного набора значений |
| `profileData` отсутствует | отсутствие дополнительного объекта | обработка продолжается; это не равно signature failure |
| `profileData` `vm_read` отказал | ошибка памяти/транспорта/копирования | профильные выходы очищаются, первичные в видимом пути не перезаписываются |
| `profileAuxSig` отсутствует | отсутствие auxiliary-объекта | auxiliary-выходы остаются нулевыми |
| `profileAuxSig` `vm_read` отказал | ошибка памяти/транспорта/копирования | ошибка журналируется, auxiliary-выходы очищаются |
| MIG-вход невалиден | транспортно-форматная ошибка | `sub_10000b194` формирует отдельный ответ с кодом ошибки |

## 5. Инвариант интерпретации

Ошибка получения auxiliary-данных не должна трактоваться как доказательство валидности, а ошибка получения profileData не должна трактоваться как доказательство невалидности подписи. В producer-коде эти события находятся после возврата `validateWithError:` и обрабатываются отдельными ветвями.

## 6. Ограничение

Нельзя по этому коду определить, как MIG-клиент отличает нулевой профильный указатель от profile mismatch, либо обязан ли он отвергать такой ответ. Это вопрос потребителя и протокола.
